# Solar-Assisted Liquid Desiccant Optimization Program Prototype

태양열 재생 Liquid Desiccant 시스템의 초기 설계 변수를 입력하고, 목표 급기 절대습도와 처리풍량에 대해 필요한 재생열량, 집열기 면적, 축열조 용량을 산정하는 웹앱 프로토타입입니다.

## 열기

`index.html`을 브라우저에서 직접 열면 됩니다.

실제 Python 계산 엔진까지 연결하려면 로컬 서버로 실행합니다.

```bash
python3 backend/server.py
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다.

## 현재 범위

- 사전 등록된 EPW/TMY 일사 및 기상 데이터가 있으면 해당 데이터셋을 그대로 사용
- 기상 데이터가 없는 지역만 위도/경도를 입력해 Sky model 기반 일사 조건을 대체 계산
- 개인 기상데이터 업로드 칸 제공
- 표준 서울 TMYx EPW 8,760시간과 사용자 업로드 ASOS 탭 구분 파일을 시간별 계산에 연결
- 분석 기간은 1년 전체 또는 1~12월 중 복수 월을 선택해 계산
- 사전 등록된 EnergyPlus/eQuest hourly load 데이터셋 선택
- 사용자가 고정한 변수는 입력값을 유지하고, 나머지 변수는 범위 안에서 반복 탐색
- 집열기 면적, 용액 농도, L/G, 재생온도 조합 반복 탐색
- 축열조 용량은 각 집열기 면적 후보의 시간별 재생열 요구량과 집열 열량 불일치로 자동 산정
- `계산 실행` 버튼을 누르면 Python 계산 엔진으로 현재 입력값을 전달
- Python 엔진은 MATLAB 최신 평판형/진공관형 로직을 기반으로 시간별 계산 수행
- 병렬 LD 모듈 자동 산정: 실험식 모듈당 권장 유량 기준 적용
- 실험식 적용범위 검사: LiCl 36.4~39.0 %, 흡수기 용액 8.05~31.40 °C, 재생기 용액 48.5~59.4 °C
- 운전 스케줄 연동: 09:00~18:00, 09:00~21:00, 24시간 조건을 시간별 LD 부하에 적용
- TES 동적 계산: 집열효율, 직접공급, 충방전 유량한계, 용량별 UA 열손실과 폐기열을 시간별 계산
- 집열기 면적별 산정: 입력 범위의 9~17개 면적 후보마다 태양열 공급량과 재생열 커버율 계산
- 1차 목표 판정: 사용자가 지정한 재생열 커버율을 처음 만족하는 최소 집열기 면적 제시
- 후보별 월별 연동: 1차 또는 2차 후보 선택 시 해당 집열기 면적·TES 용량·설계유량으로 시간별 TES 운전을 재현하고 월별 태양열 공급 및 보조열원 결과를 즉시 갱신
- 다중 후보 비교: 1차·2차 후보를 누적 선택해 월별 태양열 공급량을 색상별 막대로 비교하고, 같은 후보를 다시 선택하면 비교에서 제외
- TES 열손실: 수직 원통형 탱크(H/D=2), 경질 우레탄폼 기본 열전도율 0.023 W/(m·K), 내부 고정 단열 100 mm의 전도저항 모델

TES 열손실 기본값 근거:

- NIST/NBSIR 85-3223: 경질 우레탄폼 열전도율 0.023 W/(m·K)
- IVAR PSR 버퍼탱크: 800~5000 L 제품의 폴리우레탄 단열 두께 100 mm
- Energies 2021, 14, 6509: 탱크 구간별 열손실식 `Q_loss = U A (T_tank - T_ambient)`
- 1차 면적 산정: 목표 재생열 커버율을 만족하는 최소 집열기 면적과 보조열원 요구량 계산

## 공개 배포 방향

현재 서버는 로컬 Python 서버입니다. 임시 외부 공유는 터널로 가능하지만, 항상 열려 있는 고정 링크를 만들려면 Python 백엔드와 데이터 저장소를 클라우드 서버에 배포해야 합니다.

권장 구조:

- Frontend: 정적 HTML/CSS/JS
- Backend: Python API 서버
- Storage: 업로드 기상파일과 부하파일 저장소
- Hosting: Render, Railway, Fly.io, AWS Lightsail, 또는 학교/연구실 서버
- 최적 집열기 면적, 축열조 용량, 태양열 분담률, 보조열원, 미충족 시간 표시
- 월별 재생열 요구량과 태양열 공급량 시각화
- 지역별 적용 가능성 비교

## Vercel + Supabase 배포 구조

- Vercel 정적 호스팅: `index.html`, `styles.css`, `app.js`
- Vercel Python Function: `api/index.py`에서 계산 및 기상 API 제공
- Supabase: 사용자, 프로젝트 입력값, 계산 결과, 업로드 파일을 저장하는 역할
- GitHub `main` 브랜치를 Vercel에 연결하면 새 커밋마다 자동 배포

Vercel 프로젝트 환경변수에는 다음 공개 설정만 우선 등록합니다.

```text
SUPABASE_URL
SUPABASE_PUBLISHABLE_KEY
```

`SUPABASE_DB_PASSWORD`는 브라우저에 공개하면 안 되며, 현재 프론트엔드에는 필요하지 않습니다.

현재 계산 API는 Vercel에서 실행할 수 있지만, 업로드 파일은 서버리스 파일시스템에 영구 보관할 수 없습니다. 개인 기상·부하 파일의 영구 저장은 Supabase Storage 연결 후 활성화해야 합니다.
